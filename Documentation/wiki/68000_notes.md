# 68000 Notes
* Big Endian; 68000 stores the highest byte first and the lowest byte last. Left to right
* BSS Section. This stands for 'Block Started by Symbol'
* DC.B, DC.W and DC.L for Define Constant Byte, Word or Long
* DS (Define Storage) will define a block of data (usually initialized to zero). For example to define a block of 512 bytes DS 512 could be used
* The 68000 can only read words (including commands) on even boundaries (where the bottom bit is 0). This has a special EVEN command to do this (equivalent of ALIGN 2).

#### 68000 Registers
* 8 Data registers for general use 
* 8 Address registers for memory functions and stack pointers.
* Each register can be used as an 8,16 or 32 bit register
* Smaller is faster
* For memory pointers have be 32 bit, even though 24-bit address are only supported
* A7 is usually the stack pointer (SP) but any address register can be used as one. And you can have as many SP as you want.
* The Condition Code Register is only 16 bit, and only 8 bit can be accessed outside of Supervisor Mode.

#### Condition Control Register (CCR) Flags and Status Register (SR)
* Top 8-bits of the 16-bits is called the Status Register and can only be accessed in supervisor mode
* Lower 8-bits is called the CCR and can be accessed in user mode.
* Status register is 16 bits, can't access all of it in normal user mode, - the top 8 bits are protected, but can access the first 8 bits (Called the CCR) anytime
* The eXtend flag is used by Add and Rotate commands
* The Carry flag is used by Branching commands

```
; ==============================================================================
; CCR Flag Bitmasks
; ==============================================================================
CCR_X   EQU %00010000
CCR_N   EQU %00001000
CCR_Z   EQU %00000100
CCR_V   EQU %00000010
CCR_C   EQU %00000001

; Clear all CCR flags
CCCR    MACRO
        ANDI.B  #0,CCR
        ENDM

; Set specific CCR flag(s)
SCCF    MACRO
        ORI.B   #\1,CCR
        ENDM

; Clear specific CCR flag(s)
CCCF    MACRO
        ANDI.B  #~(\1),CCR
        ENDM

```

#### OpCode Modifiers
##### A, I, Q, and X 
* Q (Quick): e.g., ADDQ, SUBQ. This tells the CPU to embed a tiny immediate number (strictly from 1 to 8) directly inside the instruction's 16-bit opcode word. Because the number is baked right into the instruction itself, it is highly optimized—it takes up less memory and executes faster than standard arithmetic.
* A (Address): e.g., ADDA, SUBA, CMPA. You must use this when your destination is an Address Register (like A0). This is a critical feature of 68k assembly: instructions ending in 'A' never modify the Condition Code Register (status flags). This allows you to do math on your memory pointers without accidentally overwriting the results of a comparison you just made.
* I (Immediate): e.g., ADDI, SUBI, CMPI. This specifies that the source operand is a hardcoded, absolute number (an immediate value, denoted by #), rather than data pulled from a register or memory address.
* X (eXtend): e.g., ADDX, SUBX. This includes the "Extend" flag (which acts like a carry flag) from a previous operation. It is used for multi-precision arithmetic. If you wanted to add two massive 64-bit numbers, you would ADD the lower 32 bits, and then use ADDX for the upper 32 bits to ensure any mathematical carry-over is included.

##### Data Size Suffixes
Size Suffixes (.B, .W, .L): Define the width of the data. They tell the CPU exactly how much memory or register space to manipulate during that operation.
* .B (Byte): 8 bits. When applied to a register, it modifies only the lowest 8 bits. The upper 24 bits are left completely untouched.
* .W (Word): 16 bits. Modifies only the lower 16 bits. This is the M68k default. If you just write ADD D0, D1 without a dot suffix, the assembler implicitly treats it as ADD.W D0, D1.
* .L (Long): 32 bits. Operates on the entire 32-bit register.
